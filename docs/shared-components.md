# AST shared-component registry

Reuse gate + index. **Before building any control / style / token / converter / service / base / contract,
consult this registry first** (skill `rule-shared-components`). It lists the project's shared components with,
for each, its **customization boundary** — what is LOCKED (must not be changed/overridden without reporting to
the project) vs what a consumer may freely vary. It is an index, not a second source of truth: where a
LOCKED invariant already lives in a skill/canonical doc, the boundary column POINTS to that home.

Binding on every contributor. `AST.Meta.Tests` guards it both ways: nothing shared
is unregistered, and no entry dangles. Adding/removing a shared component updates this file in the same commit.

The template-part `TextBox` has `IsUndoEnabled = false` (same precedent as `AstPasswordBox`) so Ctrl+Z cannot resurrect a stale digit buffer desynced from `_editor`. **The popup Calendar never carries `Date` into `SelectedDate`** (2026-07-29 fix) — opening only navigates `DisplayDate` to the right month; `SelectedDate` stays `null` so every pick, including re-picking the date already in the field, is a `null→value` change `SelectedDatesChanged` always raises (WPF does not raise it for a same-value reselect). The current `Date` is **NOT** visually highlighted in the popup — a `CalendarDayButtonStyle` override for this was tried and reverted 2026-07-29 (dropped WPF-UI's Fluent per-cell look); do not reattempt without first inspecting WPF-UI's compiled Calendar template, and do not reintroduce a `SelectedDate` preselect. Free: `ShowCalendarGlyph`, which VM prop binds `Date`/`Today` |
